# Appllama research: borrow patterns, not entire funnels
**Source: live Appllama connector retrieval, 28 September 2026. Eight selected apps; 26 curated screen records.**

## Evidence boundary
Appllama returned app profiles, recorded flow order, screen names, UI elements, palettes and expiring media links. The media could not be downloaded in this environment, so this is a structured-screen-record study, not a visual/pixel audit. The selected records do not establish the exact current app flow in every geography, account state or experiment cohort. Flow totals can include video and variant records; they are not necessarily the number of compulsory screens a user sees.

The registry records exact app/screen IDs, observed elements, proposed adaptation and refresh calls. It deliberately excludes expiring links. Codex should open the relevant screens with `Appllama.get_screen({"screen_ref":"..."})`, view pixels when available and note any disagreement with the metadata. Do not stall unrelated implementation on unavailable research media. The approved atepdf screenshots are already bundled and remain the visual authority.

No conversion rates, retention uplift or revenue causal effect were supplied. We did not perform live purchases. No app-level financial labels are used as proof that a pattern is effective. The instructions below are hypotheses to test with atepdf users.

## 1. Jomo: relief and personality, not the whole questionnaire
Records: `1609960918/onb_4wjx1`, `onb_mblba`, `pay_dx56g`.

The intro metadata frames friction and uses approachable illustration. The offer record includes a Later exit, before/now cards and annual-plan emphasis. This supports studying a benefit-led, welcoming presentation rather than an enterprise feature list. The search/profile also exposed a long recorded onboarding collection, but only its first page was retrieved and it should not be interpreted as 38 mandatory steps.

**Adapt:** a real before/after document result and a friendly paper illustration. Copy can describe fewer steps; numerical time saved requires measurement. **Reject:** age/name/screen-time surveys, borrowed awards, invented metrics, lifetime assumptions and notification pressure. atepdf users arrive with a document job, not a behaviour-change programme.

## 2. Structured: teach by making something useful
Records: `1499198946/onb_3ypjz`, `onb_1fugx`, `onb_0pz8o`, `pay_qlhga`, `pay_55w8r`.

Recorded elements include a skippable intro, task input with suggestion chips, a useful plan summary and optional notification presentation. Its paywall remains within the app's colour language and has explicit plan choices.

**Adapt:** optional sample files + a suggested request that produces an actual local result, then one actionable next step. Keep the paywall in atepdf's approved visual system. **Reject:** requiring colour/persona setup, calendar features, notifications or a lifetime plan merely because the reference offers them.

## 3. PDF Expert: optional identity, secondary controls and plan clarity
Records: `743974925/onb_1t4kp`, `onb_95q9r`, `onb_ck431`, `pay_yriav`, `pay_8oy77`.

The sign-up record includes a Skip link. The paywall records identify restore controls, a secondary plan choice, device icons and billing captions. A separate record describes a home coachmark.

**Adapt:** account linking after value, a quiet inline first-use hint, a visible annual/monthly selector, restore access and a precise supported-device explanation. **Reject:** the reference's tool grid, early social-follow interruption, mandatory occupation selection or editor/signature feature promises. A licence shared across devices must not imply that files are synced.

## 4. Scanner Pro: show the document result
Records: `333710667/onb_bnb10`, `onb_naf6n`, `pay_1muku`.

Document safety and sharing are illustrated through a receipt/phone preview. The subscription record has feature bullets, plan cards, selection indicators and a restore action.

**Adapt:** explain processing with a real file and show exactly what can be saved. Make the plan controls readable. **Reject:** camera-first onboarding for a file-first utility, unsupported cloud storage claims and assumed trial terms. OCR is an engine action behind atepdf's composer, not a separate camera funnel.

## 5. Genius Scan: respect the free route and make help easy
Records: `377672876/pay_y6awx`, `oth_l9x40`, `oth_qmzqn`, `oth_u17uh`.

The offer record explicitly includes a secondary Basic CTA. Settings records include plan/account, storage and support groupings. Its cloud-account screen ties signup to a benefit.

**Adapt:** visible Continue free, one Plan and billing area, Restore, clear local-data controls and targeted help. This is especially useful for a solo operator who cannot manually resolve every purchase question. **Reject:** bringing the reference's cloud-sync feature into our privacy model or putting the settings categories on the main workspace.

## 6. Opal: billing timeline clarity, not repeated exit offers
Records: `1497465230/pay_2ztwr`, `pay_4zt6h`.

The annual-offer metadata includes a journey timeline and trial footnote. A second record describes a monthly downsell sheet.

**Adapt:** if an auto-renewing trial is eventually approved, explain activation, reminder when actually supported, first charge and cancellation clearly. **Reject:** implementing a trial by default or launching another sales modal after someone dismisses the first. Monthly should already be visible in the main offer.

## 7. CamScanner: keep acquisition insight separate from first value
Records: `388627783/onb_lxdlq`, `pay_drcyy`, `pay_4evzh`.

The recorded referral survey has source choices and a close control. Paywall metadata contains product proof, legal/billing captions and a selected weekly row in one variant.

**Adapt:** ask where someone heard about atepdf only after value, optionally, and compare that answer with consented attribution. Explain purchase terms adjacent to the CTA. **Reject:** copying weekly auto-renewal, proof banners that belong to another company or pre-task survey friction.

## 8. Noted: a calm plan centre
Record: `1149425482/oth_y5h83`.

This targeted record describes a plan summary, licence action and account choices. No full onboarding or checkout journey was examined.

**Adapt:** an uncluttered plan sheet with current access, renewal/expiry, provider and restore/account-link actions. Actual cancel, grace-period and receipt-error logic must come from verified provider state and primary billing documentation, not assumptions about what this screenshot does.

## The resulting product decision
Onboarding is a successful first task, not a slideshow. Monetization is a relevant continuation of value, not an ambush. Retention comes from recipes and repeat document work, not daily streaks. Self-service account and billing flows protect both user trust and founder time.
