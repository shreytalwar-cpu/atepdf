# Release, operating authority and unresolved inputs

## Build now
Local code, synthetic fixtures, deterministic engine tests, approved UI, sandbox configuration and non-public documentation are in scope. Preserve old Attenlo PDF unchanged and create atepdf separately. Use installed tools under their actual permissions; old source stays read-only. This handoff does not include the application repository or credentials and does not establish existing repository facts.

Do not solicit these all as a questionnaire at the start. Resolve what can be learned from the repository; work around independent blockers. Never create a paid account just because the spec names a service.

## Safe configuration
Provider keys are server-only. No live model traffic without configured credentials/approved budget. No live billing, campaigns, production experiments or remote document processing by default. Treat old `.env.example` values as proposals, not authority. The final `.env.example` leaves live model enablement and budgets off until intentionally configured.

Use current official provider documentation at implementation time. Settings such as `store:false` can reduce application-state retention but are not a blanket zero-retention guarantee. State which data the app sends and what the selected provider retains under the actual contract.

## Suggested release gate targets, not category benchmarks
- Supported-task pilot: >=90% completion without facilitator instruction; record sample size and exact tasks.
- Held-out supported command plans: >=95% correct with safe ambiguity handling; record semantic error severity, not only aggregate accuracy.
- No known unresolved release-blocking data leak, silent corruption, unintended input overwrite or double execution in the release corpus.
- Actual UI tests on the slowest configurations advertised, including keyboard, accessibility, suspension and cancellation.
- Verified sandbox purchases, restore, pending, expiry/refund and correct price/renewal disclosure.
- Published capabilities correspond to verified engines and language assets on each platform.

These are proposed project quality thresholds. Passing a finite corpus is not proof that every PDF works. Do not silently loosen gates to publish on an arbitrary date.

## Commercial discipline
Both financial workbooks are preserved. Their model cost, CAC, growth, pricing and retention are hypotheses. Fixed comparison charts are historical outputs; they do not recalculate merely because a user changes the workbook. Re-export charts only when a revised model is explicitly requested.

Initial rollout can be platform-staged after evidence. Do not call a four-folder repository four released products. Owner approval is required for public deployment, production configuration changes, customer communications, live charges, campaign budgets and commercial SDK obligations.

## Operational minimum before the first payer
Self-service restore/manage subscription/help; purchase and usage idempotency; monitored gateway limits; a provider outage fallback to local shortcuts; sanitized diagnostics; application-owned temporary storage cleanup; and a documented rollback/capability kill switch. No customer document can be requested for support automatically.
