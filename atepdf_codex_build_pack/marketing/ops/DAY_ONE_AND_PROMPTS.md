# First-day sequence and focused Codex prompts
The order is designed to prevent another day of installing tools instead of shipping.

## Session 1: establish product evidence
Open the NEW atepdf repository. Read the current handoff, perform the bounded old-source learning pass without writes, and prove a new local merge -> real result -> follow-up -> undo. Keep the selected shadcn + AI SDK and native architecture. A missing marketing account does not block this.

## Session 2: establish marketing context
Merge the shared product-marketing context and the needed project-authored skills into the NEW atepdf repo without overwrites. Inspect available tools. Fill the connection register with only observed status. Review selected external skills. Set zero production write authority.

## Session 3: produce one commercial slice
Create the document-pack landing page and safe preset route. Capture one real synthetic-file run. Produce three draft hooks around that footage with Remotion. Check actual rendering and claims. If the app cannot perform the claimed operation, fix it or narrow the demonstration.

## Session 4: prove data and access
Test first-payment/refund events and consent, then connect the next necessary analytics/billing service with authorised credentials. Prepare an empty actuals report and paused campaign draft. Do not wait for every optional connector.

## Prompt: connection inventory
“Inspect this Codex host and the approved repository. List which selected integrations are installed, authenticated, scoped to the right project and actually verified by a permitted read. Record evidence and gaps without exposing credentials. Do not install services or modify global settings without approval. Continue independent local work.”

## Prompt: original creative
“Read the product context, creative playbook and claims register. Produce the next three draft hooks for the document-pack workflow using genuine synthetic-file footage from the verified build. Keep one core demonstration, current price assumptions and the cloud-instruction/local-processing boundary. No invented customers, stats, badges or competitor footage.”

## Prompt: landing and conversion QA
“Test advertisement/preset -> document-pack page -> files -> instruction -> real result -> export -> next job -> relevant offer using synthetic data. Check in-app-browser handling, consent denial, keyboard, cancelled checkout and unsaved output. No ad scripts or replay may inspect the workspace. Return actual screenshots and failures.”

## Prompt: read-only campaign review
“Read only the approved account/export for the stated dates. Reconcile first payments and media cash including tax/creative. Separate annual/monthly and known/unknown attribution. Compare equal-age cohorts against the mix-adjusted CAC target. Propose keep/change/pause with uncertainty. Do not change delivery or spend.”

## Prompt: feedback-to-product
“Review the de-identified observation log. Separate observed task failures, objections and feature requests. Pick one change that improves the first or next real job without adding excluded features. Cite the observations by ID. Do not use an example record as real customer evidence.”

## Prompt: launch approval packet
“Run the launch checklist, rights/claims review, purchase tests and evidence checks. Assemble the exact account, asset hashes, page/price versions, total cash cap and dates for owner review. Leave publication disabled. A passing reference test is not live campaign authority.”

## End-of-session handoff
What was implemented, tested and observed; paths to evidence; tests not run; account/credential blockers; cost actually incurred under authority; next executable task. Do not write a replacement master plan when the next task is known.
