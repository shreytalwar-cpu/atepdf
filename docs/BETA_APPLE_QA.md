A separate launch → type → background → foreground → continue typing test with no planner and an empty conversation passed in 21.1 seconds, without the repeated warning. This narrows the reproduction but does not establish a root cause. A second minimal baseline with actual bundled import/merge, a partially typed draft, background/foreground, retained 3-page result and exact continued typing passed in 26.2 seconds without the warning. This rules out a simple populated conversation alone, while the long paired scenario remains unresolved. See [populated baseline](evidence/native/beta-ipad-populated-resume-summary.json). This rules out the async entrypoint alone; it does not isolate network suspension, cancellation, app lifecycle or XCTest behavior. ## Boundaries

Planner UI tests use `tests/native/planner/server.ts` on isolated localhost:3212. It constructs a synthetic provider, does not load the owner's API key and cannot make paid model calls. PDF operations and validation use the actual app engines. These checks do not prove hosted planning quality, real Wi-Fi, physical-device performance, signing, distribution or purchases.

Backgrounding is not documented as automatic cancellation. Session persistence is not implemented; a full relaunch should show a fresh workspace and require pairing again. Tomorrow's physical-device checks remain separate from simulator evidence.

No old-project source, scripts or runtime were used during this QA pass. New work is limited to the existing atepdf repository. Physical-device and deferred Mac interactive acceptance remain separate.
