## Native planner and interruption evidence

The isolated native TLS UI test passed: enter a masked beta pairing code, establish the pinned HTTPS connection, send a synthetic merge instruction, observe exactly one additional request at the synthetic TLS provider, receive an actual locally validated 3-page PDF, then disconnect. It used the corrected temporary certificate harness on loopback ports 3444/3445, not the owner's gateway or key. See [TLS summary](evidence/native/beta-ipad-tls-summary.json) and [connection/result-count screenshot](evidence/native/beta-ipad-native-pinned-tls-local-merge.png). This proves the native application's pinned transport path in a simulator, not physical Wi-Fi or its permission prompt.

The longer loopback test proved explicit Stop reached the synthetic server, preserved the prior 3-page result through background/foreground, and allowed subsequent typed removal and undo in one run. That run failed only at the final Disconnect control because six short test gestures did not traverse the conversation; the visible Latest message control is now used. The next run repeatedly waited 60 seconds for XCTest's animation-completion notification after foregrounding. It was stopped and is recorded as **Testing was canceled**, not a pass. No private quiescence override or speculative app fix was used. See [canceled retry summary](evidence/native/beta-ipad-planner-summary.json).

A separate launch → type → background → foreground → continue typing test with no planner and an empty conversation passed in 21.1 seconds, without the repeated warning. This narrows the reproduction but does not establish a root cause. A second minimal baseline with actual bundled import/merge, a partially typed draft, background/foreground, retained 3-page result and exact continued typing passed in 26.2 seconds without the warning. This rules out a simple populated conversation alone, while the long paired scenario remains unresolved. See [populated baseline](evidence/native/beta-ipad-populated-resume-summary.json). The observed default UIKit content category was `UICTContentSizeCategoryL`, with Reduce Motion off; native Reduce Motion-on behavior is not yet claimed.

A shorter paired test repeated the interruption failure: actual merge, pairing, one pending synthetic request, explicit Stop observed by the server, then a draft and background/foreground. The prior 3-page result remained present after the first 60-second XCTest idle wait. A subsequent composer tap waited again, and XCTest itself failed the method at its three-minute execution allowance. This is an actual [failed test result](evidence/native/beta-ipad-cancel-resume-summary.json), not only a tool wrapper timeout. Cancellation before interruption is proved; reliable post-interruption interaction in this paired XCTest scenario remains unresolved. The identical populated baseline entered through an async XCTest method subsequently passed in 23.1 seconds with no repeated idle wait. This rules out the async entrypoint alone; it does not isolate network suspension, cancellation, app lifecycle or XCTest behavior. The cause remains unknown, and paired post-resume interaction is not fully accepted. See [async baseline summary](evidence/native/beta-ipad-async-populated-resume-summary.json).

The final corrected **actual application** acceptance test passed in 66.3 seconds on `afa15b5`: Safari download → system Files picker selection and Open → two native imports → 4-page local merge → Vision OCR on two scanned pages → validated balanced compression. The current result remained 4 pages and decreased from **7,709,403 to 1,263,762 bytes**. No planner request, engine/store mock or private app-state injection was involved. This is on-simulator workflow evidence; no share destination or independently reopened saved iOS file is claimed. The next attempt reached the real Files picker and selected the expected file, but the test omitted the picker’s visible **Open** confirmation. Its full-screen screenshot proves that the picker remained open. A runtime snapshot exposed the underlying app’s “Preparing local tools” state, which must not be misclassified as an engine stall. The failed test is preserved in [summary](evidence/native/beta-ipad-files-download-summary.json) and [picker screenshot](evidence/native/beta-ipad-files-import-pending.png). The test now confirms Open before waiting for import. The next retry restored a different picker folder; an ambiguous “Downloads” text lookup did not navigate into it. That failed attempt is recorded in [summary](evidence/native/beta-ipad-files-confirmed-summary.json). The selector now targets the observed system sidebar cell, `DOC.sidebar.item.Downloads`. No application defect or engine failure was established, and no app-private container injection was used.

## Boundaries

Planner UI tests use `tests/native/planner/server.ts` on isolated localhost:3212. It constructs a synthetic provider, does not load the owner's API key and cannot make paid model calls. PDF operations and validation use the actual app engines. These checks do not prove hosted planning quality, real Wi-Fi, physical-device performance, signing, distribution or purchases.

Backgrounding is not documented as automatic cancellation. Session persistence is not implemented; a full relaunch should show a fresh workspace and require pairing again. Tomorrow's physical-device checks remain separate from simulator evidence.

No old-project source, scripts or runtime were used during this QA pass. New work is limited to the existing atepdf repository; no commit was created by this QA agent.
