# Structural page verification — SHR-47

Merge and Remove Pages now require reader-produced physical-page evidence before a result can enter the next staged step or become current. An engine success or matching page count alone does not admit a result. OCR/compression retain their existing checks because they intentionally add text or change image samples; their stronger visual/placement verification belongs to SHR-48.

`Inspection.structure` is local, versioned, reader-specific evidence: each page has a SHA-256 of an orientation-neutral raster no larger than 96×96, MediaBox/CropBox origins and sizes, and canonical rotation. Text is independently compared as well. Image-only pages need no OCR. A fingerprint identifies the reader's bounded page signal; it is not a persistent globally unique page ID. Identical/indistinguishable signals cannot establish distinct provenance, and fine changes below this resolution can escape detection. No pixel-perfect, font, annotation-appearance or OCR-placement guarantee is made.

Apple's PDFKit/CoreGraphics reader supplies both box dictionaries and raster fingerprints independently of the pdf-lib writer. PDF.js supplies browser raster/text identity; exact original box values are supplementary checks from the existing pdf-lib dictionary reader because PDF.js exposes the visible intersection rather than both raw boxes. Android retains its existing narrow default-geometry admission; its PdfRenderer fingerprint is independent, while exact box values supplement its integer dimensions from shared admission. Neither supplementary path is claimed to be a second independent geometry parser. Comparisons happen within one reader/profile, never between different platforms' raster hashes.

`expectationsForStep` maps each requested output slot to its exact input reference and physical source page. Merge follows input order; Remove excludes the validated physical indices. `expectPages` accepts an explicit mapping and optional intentional rotation override for later tools. Source mappings and geometry are cloned before the engine awaits, and bound to the accepted workspace revision. Later reorder/rotate/split adapters can reuse this contract; Images→PDF needs an image-specific expectation adapter. These contracts do not add or advertise those executors, relax plan validation, or exempt unrelated properties from checking.

`verifyPages` requires complete version/profile evidence, exact expected count, ordered fingerprints, normalized text, rotation, and both box origins/sizes (0.01-point numerical tolerance). The existing displayed dimensions/text checks remain. Missing or malformed evidence fails closed. Fresh independent inspection recomputes the result signal. Revision checks bracket execution/inspection, the verifier checks its bound revision, and the existing atomic store commit checks revision again after asynchronous preparation. Cancellation checks and reader cleanup apply throughout. Any failure clears the transient receipt; bad bytes stay unpublished, the previous result/history remain available, and rejected artifacts add no Undo entry.

The renderer keeps only one tiny identity bitmap per inspected page; at most 100 pages are admitted under current unchanged safety guards. Hash/bitmap work is sequential; at 96 pixels per side the bitmap ceiling is 36,864 bytes per page and 921,600 pixels over 100 square pages. Source/result fingerprints and mappings are small metadata. Original image decoding still uses existing parser/decoded-image bounds; a tiny final bitmap does not itself bound all decoder memory or eliminate the separately recorded encoded-dimension mismatch gap. Existing controller/worker/native deadlines remain. Browser render tasks can be cancelled; native cancellation is checked around synchronous CoreGraphics rendering, which cannot be interrupted mid-call.

The evidence is not sent in planner requests, transcripts or user error messages. Workspace checkpoint projection continues to omit these transient fields; restore independently re-inspects retained PDFs and recomputes them, so no persistence schema migration or replay is introduced. Old/absent inspection evidence never silently substitutes for a fresh gate pass. The matrix uses schema v2 with required operation-specific production receipts; v1 schema/results are preserved. A historical structural/readability pass does not imply the new gate or full visual checks passed.

Tests generate wrong PDFs by swapping same-size scans, keeping the wrong scan, shifting CropBox/MediaBox origins, changing rotation/order/count, then feed them through the actual writer/controller/reader boundary. Positive corpus, saved reopening, Undo, stale callbacks, cancellation and unavailable evidence are separate tests. The same mutation suite runs against the compiled Apple reader. Native helpers/builds remain distinct from interactive Mac-app acceptance.
