# ADR 0009 — Private Apple-device beta connection

This extends ADR 0008 for the owner's private Mac, iPhone and iPad beta. It does not introduce production accounts or a public deployment. The browser and ordinary launcher remain loopback-only. An explicit device-sharing launch may bind a separate TLS listener to one canonical private IPv4 address on port 3443. All current automated tests use loopback; physical Wi-Fi acceptance is still required.

The separate listener exposes only native pair, planner, status and disconnect routes. It refuses browser Origin/fetch context, incorrect Host, unknown paths and oversized requests. It forwards only the allowed headers and bounded instruction/anonymous metadata to the existing gateway in memory. It serves no website, files, key setup or pairing-code issuance. The existing gateway retains one-use pairing, bearer authentication, request validation, concurrency and the remaining owner-approved allowance. Starting the listener or pairing makes no paid call and grants no new allowance.

A fresh private seven-day CA and non-CA leaf with the exact IP SAN are created for the opted-in launch. The issuer's private key is removed after leaf creation. Files are restricted to an owned private directory; existing material is never overwritten and system trust is never changed. Pairing codes carry the private endpoint, exact SHA-256 leaf certificate fingerprint and five-minute one-use secret. The user transfers the masked code directly from the local browser to the native app. Restarting either side requires pairing again.

The native transport accepts canonical private IPv4 HTTPS origins, a bounded code and a current expiry. Physical iOS rejects legacy plain-HTTP codes. It checks the exact leaf pin, anchors only the supplied private issuer for that session, and still evaluates TLS hostname, validity and server usage. It disables network issuer fetching before any trust evaluation and uses the same delegate for session and async task challenges. Redirects are rejected by the async task delegate. There is no accept-all certificate branch, system certificate installation or arbitrary-loads exception. Native requests use ephemeral URLSession storage, TLS 1.2 or newer, no cookies/cache/credential persistence and no cellular connection.

The OpenAI project key stays in the Mac gateway. Session bearers stay in Swift actor memory and server-side hashes; neither appears in JavaScript, preferences, saved chats or logs. PDF bytes, filenames, paths, OCR text, previews and document checksums remain on the processing device. A local TLS certificate fingerprint is a connection credential, not a document checksum and never model input.

Simulator tests can prove application pairing and local PDF execution through the pinned transport. They cannot prove a physical Wi-Fi route, local-network permission prompt, device provisioning, Files export or mobile memory behavior. Those checks remain in F09/F10 and `BETA_DEVICE_ACCEPTANCE.md`. Android remains deferred; commercial and release authority is unchanged.
