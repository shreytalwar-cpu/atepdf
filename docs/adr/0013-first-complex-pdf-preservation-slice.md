## 1. Approved decision

Choose **preservation of simple absolute HTTP/HTTPS URI Link annotations during Merge only**, in otherwise admitted, unsigned, unencrypted PDFs. Use the existing pdf-lib writer and PDFKit independent reader. Add no engine or dependency. This is a finite compatibility exception, not support for complex PDFs generally or annotation creation/editing.

The evidence supports feasibility, not shipping readiness. Direct copying preserved the fixture's URI bytes and rectangle, including after a preceding input moved the linked page to output page 2. However, optional annotation `/P` references were copied to detached page objects. SHR-50 must prevent that and prove correct page attachment before admission changes. The existing reader/controller reports only page dimensions, rotation and text; it cannot currently enforce link preservation.

Why this slice: web links have plausible everyday value, do not target pages in another part of the PDF, and have a small independently measurable preservation contract. Corpus frequency is not a measured customer-demand estimate. Internal links, outlines, forms and tags require substantially more document-wide graph reconciliation. Ordinary annotations introduce appearance, popup/thread and subtype semantics. Merge avoids deleted-target policy and is the smallest operation increment. URI-only Remove probes were encouraging, but do not justify expanding the first delivery to another operation before Mac promotion verification exists.

### Bounded probe observations

Twelve saved inputs/outputs were inspected by PDF.js 6.3.289 and strict pypdf 6.10.0 using installed pdf-lib 1.17.1. Two temporary URI-only projections retain the corpus's actual link while removing other families **only in experiment copies**; one adds a valid `/P` pointing to its source page. These are not new committed corpus fixtures or a production stripping strategy. No production guard was disabled or changed.

- Original internal destination points to input page 2. After ordinary appendix + interactive Merge, expected output target is page 3; actual destination reference belongs to no output page. After removing input page 2, the retained link still references a detached copy of that deleted page.
- URI-only Merge before/after an ordinary input retains exactly `https://example.invalid/shr45`, its original string bytes and rectangle `[55, 682, 265, 710]`. URI-only Remove retains that link when its page stays, and leaves zero links when its page is deleted.
- `/P` is valid in the added test input, but does not belong to the output page tree after copying. This must fail a preservation oracle even though PDF.js finds the URI and rendering is unchanged.
- Four sampled page pairs have identical decoded pixels in Poppler 26.05.0 at a maximum dimension of 900. The interactive output's highlight, note and widgets look intact in the reviewed rendering despite broken form/navigation semantics. This is sampled appearance evidence, not whole-document/OS fidelity or click validation.
- Original fixture hashes remain unchanged. Detached objects and discarded catalogs explain why simply removing the Annots/catalog guards is unsafe.

No app build, real Mac acceptance, signature authentication, new engine build or customer-document test was performed. Signed PDFs are absent from SHR-45/46; their current signature-specific behavior is **unverified**.

## 3. Preservation semantics by operation

These contracts compare source identity and output page-tree membership, not object numbers or parser success. Object numbers may legitimately change. Merge mapping is `(input identity, physical page) → sum of preceding input page counts + physical page`. Remove mapping is retained physical page → its rank among retained pages; removed pages have no output mapping. Reorder is outside this task; any later support must use an explicit permutation, not reuse offset arithmetic.

| Family | Merge preservation means | Remove preservation means | Current-stack feasibility / later alternative |
| --- | --- | --- | --- |
| URI Link | Same annotation multiplicity on mapped containing page, exact URI string bytes, rectangle, declared style/flags; valid optional `/P`; no extra action or network request | Retained pages keep the same URI semantics; annotations on removed pages cease to exist; no link to a detached page | Finite with existing low-level dictionaries and page map, but `/P` copying and independent checks need bounded implementation. PDFKit is a potential writer fallback, not required. |
| Internal destination | Every explicit/named destination points to the intended output page, with destination mode/coordinates/zoom retained; namespace collisions resolved explicitly | Kept targets remap by retained rank; deleted-target links must be refused or removed only under a separate explicit policy. Keeping a detached target is unacceptable | Current copying demonstrably fails. Custom page/destination and name-tree reconciliation needed. PDFKit destination APIs or libqpdf helpers are candidates, neither proven here. |
| Ordinary annotations | Exact declared subtype/content, rect/quad geometry, flags/colors/opacity, appearance resources and page binding; popup/reply/thread graph retained where claimed | Only removed-page annotations disappear; retained annotations and relationships remain valid, with explicit policy for cross-page replies | Direct copies preserve the two simple specimens only. A per-subtype whitelist, appearances and relationship validation are required; PDFKit or MuPDF APIs are possible local alternatives, not general preservation guarantees. |
| Outlines | Preserve source hierarchy/order/titles/style/open state, with a declared deterministic policy for combining roots; every target maps to an output page | Retained destinations remap; deleted targets require an approved prune/refusal policy; parent-child hierarchy must remain coherent | New output lacks catalog root. Needs explicit tree reconstruction and destination mapping even with PDFKit or qpdf. Not a first-slice change. |
| Forms | Preserve field/widget trees, types/names/values, appearance states/resources, widget-page binding and valid object references; collisions and calculation/actions require explicit policies; no silent flattening | Remove only widgets on removed pages; reconcile surviving fields/widgets and resources without dropping values or leaving dangling references | Current copying loses discoverable fields. pdf-lib form APIs do not make cross-document field migration automatic. qpdf AcroForm helpers or MuPDF could be investigated separately; XFA and scripting remain distinct refusals. |
| Tags | Preserve logical reading order, role/class mappings, StructElem parent/child relationships, page/MCID/OBJR bindings and ParentTree; namespace/key collisions remap | Prune removed-page references and keep remaining structure/reading order/ParentTree coherent | Current Merge loses root. Requires document-wide reconstruction plus an independent structure/accessibility oracle. No candidate was demonstrated safe. No PDF/UA conformance claim. |

## 4. Exact approved first envelope

**Operation:** Merge all pages in explicit input order only. **Inputs:** otherwise currently admitted unencrypted, unsigned PDFs; each annotation must pass the profile below. An ordinary PDF may be mixed with a profile PDF. All inputs must pass before a result can be promoted. A URI alongside a form, internal link, bookmark, tag or unsupported annotation refuses the whole job; do not discard that other feature.

**Simple web-link profile (approved, CPDF-1):**

- `/Subtype /Link`; optional `/Type` must be `/Annot`. Exactly one `/A` URI action: optional `/Type /Action`, `/S /URI`, `/URI` a string containing an absolute ASCII HTTP/HTTPS URL with a nonempty host and no control characters. Preserve original bytes without decoding/re-encoding, URL normalization or fetching. Relative URLs, catalog URI bases, other schemes, credentials, `/IsMap`, action chains and additional action keys are outside this first slice.
- `/Rect`: exactly four finite numbers, ordered with positive area, expressed in the unchanged page coordinate system. Preserve MediaBox/CropBox origins, rotation and visible placement; do not translate just because output page number changes.
- Only these annotation keys: `Type`, `Subtype`, `Rect`, `A`, `P`, `Border`, `BS`, `C`, `H`, `F`. Unknown keys refuse. `P`, if present, must reference the actual containing source page; output must point to its actual mapped page. No recursive copying of the original page through `P` may leave detached page graphs.
- Optional appearance style stays exact: `Border` is three nonnegative numbers with an optional finite nonnegative dash array; `BS` contains only optional `Type=Border`, nonnegative finite `W`, `S` in `S/D/B/I/U`, and a finite nonnegative `D` dash array; `C` is 0/1/3/4 finite components in `[0,1]`; `H` is `N/I/O/P`; `F` is an integer using only defined annotation flag bits. Invalid types, contradictory/unhandled style combinations or unresolved references refuse. SHR-50 must exercise each allowed variant; unverified variants cannot quietly ship.
- No `/AP`, `/AS`, `/QuadPoints`, `/Dest`, `/AA`, `/StructParent`, `/OC`, popup/reply/thread keys or widget/field properties. Marked/tagged/page-structure indicators and catalog destinations/name trees remain refused, including legacy `/Dests`; the current guard list alone is not exhaustive detection.

This is preservation of existing approved-profile annotations, not a feature for creating/editing annotations. Technical traversal/resource bounds remain separate from commercial allowances. Bound every new object walk/string/array decode and test malformed/cyclic graphs; do not invent a larger public page limit here.

### Remaining refusals after the approved implementation

Merge still refuses internal/named/remote GoTo links, relative/non-HTTP(S) URI actions, launch/JavaScript/submit/reset actions, every other annotation subtype (including Text, Highlight, Ink, Popup, Widget, FileAttachment and RichMedia), custom appearances, optional content, outlines/bookmarks, destination/name trees, forms/XFA, tagged structure and digitally signed/certified/signature-field inputs. Existing collections, active-content, drawing, damaged/encrypted and resource refusals are unchanged except for the expressly approved URI profile.

**Remove Pages remains unsupported for every nonempty annotation input, including this URI profile.** OCR/Compress and other tools gain no complex-input support from this decision. Merge results with preserved links must retain this operation restriction when reused, restored or reimported. An operation outside the profile refuses before transformation; it must not silently strip links.

## 6. Digitally signed PDF policy (CPDF-4)

**Approved: refuse digitally signed, certified or signature-field PDFs for v1 content-changing transformations, including Merge and Remove.** Also refuse empty signature fields under the form refusal. Explain that transforming the PDF could invalidate its signature or certification and ask for an unsigned source copy. Do not strip signatures silently, offer warning-and-continue, or claim signature preservation. Preserve the original bytes and existing access/export controls. A visible signature appearance does not prove authenticity; detecting signature structure is not cryptographic verification or signer trust validation.

The writer creates and rewrites a new document. It has no verified incremental-update/certification-permission preservation path. Some signature workflows allow specific incremental changes; that does not authorize this writer's page transformations or validate signatures on its new output. Signature-looking raster marks without digital signature structures are ordinary page content, with no authenticity claim.

Current AcroForm/Perms/Annots guards reject common signed structures, but there is no dedicated signed-input classifier or genuine signed corpus evidence. SHR-50 must fail closed on field `/FT /Sig`, signature dictionaries `/Type /Sig` or `/DocTimeStamp`, `/ByteRange`/signature-content structures, certification/DocMDP/FieldMDP/Perms, inherited/indirect and malformed signature indicators; bounded traversal ambiguity refuses. Byte scanning alone is insufficient. No signed-input support can be inferred from generic rejection. This approved policy adds no runtime detection in SHR-49.
