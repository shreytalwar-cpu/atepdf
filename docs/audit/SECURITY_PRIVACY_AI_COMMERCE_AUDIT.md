# Security, privacy, AI and commerce audit — prototype-v0

Date: 29 September 2026. Frozen source: `5a6c0c542603cdb2a72bcdb2a91958ef3b6f12ab`, verified at the start and end of source review. This is a **read-only source audit**, not a penetration test, runtime network capture, provider-retention verification, or release approval. Only this document was written. No application/test/configuration edits, builds, tests, services, provider calls, installations, simulator operations, credential reads, or external contacts occurred.

The implemented design keeps document processing local, projects planner metadata explicitly, and validates complete model proposals before executing allowed local operations. It also has meaningful private-development transport controls. It does **not** implement production account authentication or commerce. Four source-backed issues are recorded below: three Medium and one Low. None establishes an observed compromise; exploitability conditions are stated separately. Additional hardening and unknowns are not counted as confirmed vulnerabilities.

## Actual request and data flows

1. **Current UI → private request.** `apps/universal/App.tsx:138–144,169–199` handles Send; quick actions enter the same preparation path at `118–126`. `privateInstruction` is applied to the user's text and local artifact metadata at `176`, then `JobController.request` builds the manifest (`packages/core/src/job-controller.ts:57`). `packages/contracts/src/protocol.ts:19–29` explicitly projects opaque ref, kind, page count, byte count, selection, focus, original refs, revision, locale, capabilities and OCR language. It does not spread `Artifact`, bytes, names, checksums or inspection text into the request. Previous plan/history are empty. The current manifest includes retained artifacts, including earlier outputs, rather than only the focused result.
2. **Browser → local gateway.** `packages/planner/src/client.ts:8–15,25–34` calls status, planner, pairing issuance and masked key setup on relative `/api/...` routes. `apps/universal/src/platform/planner.web.ts:1–4` is the active adapter. `apps/web/src/app/api/planner/{route.ts,status/route.ts,key/route.ts,pairing/route.ts}:1–4` and `apps/web/src/app/api/native/[...path]/route.ts:1–5` delegate to the singleton gateway in `apps/web/src/services/local-gateway.ts:5–6`. The optional Next root serves the exported universal HTML directly (`apps/web/src/app/route.ts:5`). The older `apps/web/src/features/workspace/Workspace.tsx` has no caller in the inspected app routes; it is not the current planner UI. `apps/web/src/services/planner.ts:2` only re-exports a schema.
3. **Apple → paired companion.** `apps/universal/src/platform/planner.native.ts:7,22–28` requires available native planner plus isolated PDF storage, validates the same request, and passes only serialized DTO data into `AtepdfPlannerTransport`. Swift holds the bearer internally, returns no bearer through status, and sends to four fixed native paths (`apps/universal/modules/atepdf-planner/ios/AtepdfPlannerTransport.swift:41–61,120–128,150–174`). The Wi-Fi listener rewrites an allowed native request into a loopback gateway request and forwards only content type and authorization (`packages/planner/src/native-beta.ts:30–51`), sharing the same provider, lock and allowance.
4. **Gateway → provider.** `packages/planner/src/gateway.ts:18–73` checks host/origin/authentication/content type, reads at most 24,000 request bytes, validates and projects again (`request.ts:4–13`), reserves an allowance, and calls the provider once. `provider.ts:8–23` sends the instruction/metadata JSON plus maintained product knowledge through an OpenAI Responses model; three tool schemas have **no server-side execute function**. One complete tool call is required. PDF bytes, preview pixels and OCR text are not automatically sent back to the model. Later requests can include permitted metadata for retained output artifacts. Endpoint override caveat: F01.
5. **Proposal → local output.** `schema.ts:37–49` validates and rebinds output labels to fresh opaque refs. Browser/native clients validate response/request/revision binding (`client.ts:17–23`); App checks current workspace revision, handles undo/chat separately, and retains a choice for lossy compression (`App.tsx:195–208,213–225`). `protocol.ts:31–70` permits four known operations, at most four steps, existing/earlier refs, bounded page counts and one terminal output. `job-controller.ts:62–107` snapshots the accepted plan, checks actual local facts/capabilities, rejects duplicate execution, stages all steps, independently inspects outputs, and commits once. Schema validity is not proof the model understood a user's intended page/order.

## Findings

### F01 — Medium: inherited provider endpoint can redirect a saved key and instruction metadata

**Known implementation, conditional exposure; not reproduced.** `packages/planner/src/provider.ts:9` supplies `apiKey` but does not supply/validate `baseURL`. Installed `node_modules/@ai-sdk/openai/src/openai-provider.ts:207–215` reads `OPENAI_BASE_URL` before its default; `219–226` attaches the supplied key as Authorization. PU `src/validate-base-url.ts:3–11` rejects only an empty override, not an alternate host or plain HTTP. PU `src/post-to-api.ts:98–107` fetches that URL with the body and headers.

**Conditions/impact:** an enabled gateway launched through an environment-inheriting path (Next scripts at `package.json:6–8`, or `expo:preview` at `16` → `scripts/serve-expo.mjs`) has a mistaken or attacker-influenced `OPENAI_BASE_URL`, and the owner sends a request. The alternate endpoint can receive the saved provider key and allowed request text/metadata. This is not an unauthenticated HTTP caller's ability to change the endpoint. No actual environment value or live destination was inspected. The supported detached beta launcher filters environment variables and omits this variable (`scripts/beta/web.mjs:109–111`), materially narrowing current exposure.

**Disposition: REFACTOR provider construction.** Make the intended endpoint trust boundary explicit across launch paths while preserving test fetch injection. Minimum regression proposal: synthetic inherited endpoint override cannot redirect the production adapter's key/body; intentional adapter tests still work; beta environment filtering remains intact. No network/provider execution is required to test request construction.

### F02 — Medium: documented alternate preview server lacks canonical static containment and a static Host guard

**Known implementation, conditional file disclosure; not reproduced.** `scripts/serve-expo.mjs:18` checks lexical `resolve` containment, then uses `stat` and `readFile`, which follow symlinks. It does not check Host for static routes (`11–19`). This remains an advertised path (`README.md:14`, `package.json:16`). The supported beta server instead rejects foreign Host values and checks `realpath` containment (`scripts/beta/server.mjs:74–75,111–113`); existing tests specifically cover those controls only for that beta server (`scripts/beta/beta.test.mjs:143–154`).

**Conditions/impact:** the alternate server is running and its export tree already contains a symlink to a readable outside file; a loopback HTTP client requests the corresponding asset. A hostile website additionally needs successful DNS rebinding/local-network browser access to read through its own origin. Neither that browser behavior nor a sensitive symlink was observed. Ordinary lexical traversal is rejected. Without an escaping symlink, no private-file exposure is established. The shared gateway independently rejects non-loopback hostnames (`gateway.ts:18–21`), so the static defect does **not** establish a planner-token/key-route bypass. Missing gzip is a performance difference, not a vulnerability.

**Disposition: REPLACE alternate static host with the guarded hosting path, or remove the duplicate advertised entry point.** Minimum regression proposal: one common set of foreign-Host, symlink-escape and normal-asset cases applies to every supported launcher. Preserve loopback binding and API validation. No change was made.

### F03 — Medium: privacy disclosure is stronger than free-form instruction filtering can enforce

**Known privacy gap; no observed sensitive transmission.** `privacy.ts:3–9` recognizes particular secret/path/encoding/filename patterns. `11–34` aliases exact known names and rejects full extracted pages or matching five-word spans. It does not prove absence of arbitrary personal information, secrets expressed in other syntax, or short excerpts from a longer page. For example, a short sensitive phrase copied from a longer page need not meet either snippet condition. Text absent from extraction, including unrecognized scan content, is unavailable to this local comparison. The server cannot repeat document-aware checking because it intentionally lacks that content (`request.ts:4–13`).

**Conditions/impact:** AI is enabled and the user types sensitive content not recognized by the heuristics. `App.tsx:176–193` and `provider.ts:10` then carry the admitted instruction to the provider. This is user-entered text, not automatic PDF upload or a projection leak. Nevertheless, the privacy modal's categorical statement that passwords/paths/document contents “are excluded” (`App.tsx:273`) overstates the guarantee. The maintained AI knowledge already acknowledges the limitation (`docs/AI_PRODUCT_KNOWLEDGE.md:24–27`).

**Disposition: REFACTOR disclosure and privacy contract around the actual guarantee; KEEP positive projection.** Minimum regression proposal: synthetic short excerpts, alternate secret phrasing, exact aliases, unknown filenames and non-extracted scan text have explicit documented outcomes; outbound canary checks distinguish document metadata/bytes from free-form instruction risks. Do not claim another regex can guarantee arbitrary sensitive-text detection. The owner-approved direct Send flow does not itself require reinstating a confirmation dialog.

### F04 — Low: rejected sensitive composer text remains in the visible conversation

**Known local retention behavior; not a network leak.** `App.tsx:144` appends the raw submitted text before `privateInstruction` runs at `176`; rejection only adds an error at `210`. Entries remain session state (`59,68`) and are fed to assistant-ui (`254–256`), whose text renderer displays selectable text (`src/components/assistant-ui/elements/thread.aui.tsx:841–851`). Thus a recognized password/key pasted into the ordinary composer can be blocked from transport yet remain visible in the user message. The dedicated masked key setup correctly avoids the conversation (`357–365`).

**Conditions/impact:** the user pastes a secret into the composer and sends it; a viewer, screenshot or local accessibility consumer can subsequently see that text. No automatic chat persistence/export was found. `tests/e2e/planner.spec.ts:94–99` asserts no transport for a rejected secret but does not assert the rejected canary is absent from chat; the separate dedicated-key test does (`101–107`).

**Disposition: REFACTOR rejection handling.** Minimum regression proposal: for a recognized rejected secret, verify no planner POST and no retained visible secret in conversation, while ordinary rejected requests remain understandable. This is separate from attempted guaranteed memory erasure.

## Additional boundaries, suspected risks and unknowns

- **Response memory bounds — Low hardening gap, not a demonstrated exploit.** The Swift client limits JSON to 256,000 bytes (`AtepdfPlannerTransport.swift:170–172`). The browser client uses `response.json()` without a byte cap (`client.ts:12–15`). Upstream provider Responses uses `createJsonResponseHandler` (`node_modules/@ai-sdk/openai/src/responses/openai-responses-language-model.ts:855–864`), which calls PU `src/response-handler.ts:90–103,197–205` and the SDK's default **2 GiB** size limit (`src/read-response-with-size-limit.ts:15,30–44,61–100`). It is incorrect to call the provider read unbounded; it is also incorrect to imply the native 256 KB boundary protects gateway memory. Large malformed responses from an untrusted/misconfigured endpoint can cause substantial allocation before schema rejection. Minimum future check: a small synthetic transport byte limit test independent of the owner-approved absence of a model output-token cap.
- **Local-process authority is deliberate but narrow.** A local process able to make arbitrary loopback requests can obtain status/token and spoof Origin; no OS-user binding exists at HTTP level (`gateway.ts:37–39`). Malicious code running as the repository owner is already inside the credential trust boundary. Other-user protection on a shared host is not established. No production-auth bypass is claimed where production auth is absent.
- **Malformed model text is not code.** Non-plan replies are bounded and partially screened (`reply.ts:4–14`), then rendered as text, not HTML. The filter does not prove factual accuracy or comprehensive exclusion of all secret/filename/path forms. No current arbitrary code, shell tool or remote PDF executor was found. The native admission layer is intentionally a shape/size gate (`AtepdfPlannerTransport.swift:99–106`); TypeScript plus server schema/semantic checks carry the detailed contract validation.
- **Native local storage is not memory-only.** Disposable PDF copies are written by `runtime.native.ts:26–35`; successful iOS share copies intentionally last until startup (`92–96`). Preview output has 0700/0600 permissions, backup exclusion and iOS protection settings (`AtepdfPDFEngine.swift:115–125`). The read-only review did not establish equivalent explicit protection attributes for every picker/share scratch copy or OS backup behavior. Engine URL resolution is canonical and root-scoped (`224–244`). Physical-device storage, screenshots, clipboard and system cloud-provider behavior remain unknown here.
- **No analytics does not mean no operational data.** Local evidence tooling may record synthetic planner request bodies (`tests/live/planner.live.ts:11–14,39–47`). That runner is separate from normal package test scripts and requires explicit approval (`1–9`); it must not be casually repurposed with private documents. Crash reports, OS logs, dependency internals and hosting-provider logs were not comprehensively audited. `PrivacyInfo.xcprivacy:43–46` declares no collected data/tracking; its distribution-policy adequacy for optional AI requires a separate current-policy review, not an inference from this source audit.
- **CSP is useful but not an XSS proof.** Active hosts restrict connections/assets to self and disallow frames/objects, but permit inline script/style and WASM (`scripts/beta/server.mjs:12`, `serve-expo.mjs:10`, `apps/web/next.config.ts:3`). No exploitable injection sink was demonstrated. Worker isolation does not protect selected files from malicious same-origin JavaScript. Dependency vulnerability status and the complete parser attack surface remain unverified.
- **Next metadata is not the served HTML contract.** The optional host's `layout.tsx:3` defines robots noindex, but `app/route.ts:5` returns raw exported HTML. The inspected host responses do not add `X-Robots-Tag`. No runtime export HTML check was performed; actual robots metadata is unknown. This is a deployment/readiness observation, not a local secret-disclosure finding.
- **Historical evidence contains superseded statements.** `docs/PRIVACY_TEST_REPORT.md:2` marks older claims historical, while `10,16,25` still mention no tools, native AI disabled, or the removed token cap. Current source has three proposal tools, native pairing, and no app output-token cap. Treat historical tests as evidence for their stated artifact only. No fresh pass count is asserted here.
