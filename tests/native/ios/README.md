# Native UI workflow test

`AtepdfWorkflowUITests.swift` is an XCTest UI test of the real Release app. It imports only the bundled `brief.pdf` and `appendix.pdf`, merges them, reads two inline preview pages, types a physical-page removal command, undoes the change, and opens/dismisses the system share sheet without selecting a destination.

The test uses existing accessibility labels and result identifiers. It does not replace the PDF engine, initialize a fake store, inject a plan, read any key, call an API or exercise billing. Screenshots and the final accessibility hierarchy are retained in its `.xcresult` bundle, including on failure. A share-sheet dismissal is not evidence that a PDF was saved outside the app.

Run the `atepdfUI` shared scheme in Release on an iOS simulator through XcodeBuildMCP `test_sim`. Use the repo's current Apple development toolchain and a separate result bundle in `docs/evidence/native/ios-ui-*`. Do not claim success until the actual XCTest result passes. Physical-device behavior, memory pressure, and save/reopen through a selected system destination remain separate evidence.

The scrolling helper scopes gestures to the `conversation` element, uses short measured drags, and checks actual viewport intersection as well as accessibility hittability. React Native can expose offscreen controls as hittable, and the system keyboard adds its own scroll view; neither is accepted as proof that a preview control is visible. The composer is typed through XCTest keyboard events and its exact value is asserted before Send. No programmatic value replacement, slow-character workaround, or injected command is used.

During development, the fifth run stopped before Send because normal fast typing produced `page 2re` instead of `remove page 2`; its screenshot and hierarchy are retained in `docs/evidence/native/ios-ui-fifth-*`. The sixth run reproduced the same incorrect text with supported iOS `autoCorrect`/`spellCheck` props disabled; those ineffective props were reverted. React Native documents those [input props](https://reactnative.dev/docs/textinput#autocorrect), and upstream reports describe related [controlled-input caret interference](https://github.com/facebook/react-native/issues/44157) and [newer predictive-text interference](https://github.com/react/react-native/issues/57725). Those reports motivate the bounded mitigation; they do not prove the internal cause of atepdf's observed failure. The [assistant-ui IME issue](https://github.com/assistant-ui/assistant-ui/issues/4506) is a distinct report, not evidence that its web fix solves native input.

A narrow package patch applying public `flushTapSync` to native text changes also failed the seventh run and was reverted. The original pinned package, lockfile and workspace metadata are restored. The native adapter now uses assistant-ui's public ComposerInput extension slot with an uncontrolled React Native TextInput: native text/caret remain authoritative, changes mirror to public composer.setText, and public composer.send clears the field. Thread, Send, runtime and web input remain upstream. No pending-acknowledgement history or private renderer API is used. Edit/retry/voice prefills are not enabled and would require explicit native handling and tests. See `docs/evidence/native/native-composer-investigation.json` for failed-candidate evidence.

`testNativeComposerPreservesFastTypingAndBackspace` is the focused native regression. It types normally, asserts the exact value, inserts one character, deletes it through the keyboard, and asserts the original text again. The full workflow repeats these checks before Send, so display-only correctness cannot substitute for the actual typed PDF action.

Baseline evidence before the later frontend refinement: both the focused typing/backspace test and complete workflow passed on the real Release iPhone17Pro iOS27 simulator. The workflow includes native PDFKit raster page navigation, exact first and second typed commands, both send resets, actual 3→2→3 page results, and presenting/dismissing the system share popover without selecting any destination. `docs/evidence/native/ios-ui-result.json` records source hashes, built/installed binary equality, test artifacts and timestamps. Subsequent source edits after that bundle are listed explicitly; the refined interface needs another native run. Earlier iPad evidence remains launch-only on its earlier binary.

The first refined-interface run passed exact typing and reached the full 3→2→3 PDF workflow, including the bounded native preview. Its final Save action remained below the 190-point keyboard-open conversation after the helper's six short drags, each of which moved correctly. `ios-ui-polish-result.json` records this actual failure and screenshot. The workflow now uses the visible `Latest message` control before applying the same viewport/hittability checks to Save; it does not relax visibility or increase the scrolling bound. The owner subsequently changed the browser planning flow, so the final combined source requires another run.

The direct-planning source then passed both native tests; `ios-ui-direct-result.json` records the exact source and matching built/installed artifacts. Subsequent visual inspection found content drawn too small inside the native raster's white page, which the UI assertions do not detect. Native engine scaling is being reviewed independently before the next final build. A successful interaction test is not a pixel-fidelity assertion.

Final corrected-renderer evidence: `docs/evidence/native/ios-ui-renderer-result.json` records both native tests passing against the exact final source and matching installed/built app artifacts. The final page-2 screenshot was viewed and confirms corrected full-page content scale; precise pixel anchors and OCR positioning are covered separately by the Apple engine harness. Both Send resets now also assert the official Send button is disabled, and its native styling visibly reflects that state. The same final exported web source passed all 17 browser regressions. No paid model call, physical device, selected iOS share destination, signing or public release is implied.
